# BioFIA website

Source for [biofia.org](https://biofia.org), designed in Claude Designer and deployed as a static site on **Firebase Hosting**.

## Structure

```
public/                 Everything that gets deployed (Firebase Hosting "public" dir)
  index.html            Home
  alliance.html         The Alliance
  protocol.html         The Protocol
  working-groups.html   Working Groups
  support.js            Claude Designer's client-side runtime (renders the <x-dc> templates
                         in each page — do not remove or rename)
  _ds/                   Design system tokens/CSS/JS bundle used by every page
  assets/                Images and partner logos actually referenced by the pages
  robots.txt, sitemap.xml
firebase.json           Firebase Hosting config
.firebaserc             Points this repo at the "biofia" Firebase project
.github/workflows/      CI: auto-deploy on push to main, preview deploy on PRs
infra/                  Optional Terraform for the Firebase/GCP project itself (see MIGRATION.md —
                         this project was previously wired for Firebase App Hosting)
```

Nothing here needs a build step. The pages load React, ReactDOM and Babel Standalone from the
`unpkg.com` CDN at runtime and compile the page's inline JSX in the browser — that's how Claude
Designer exports work. That means the site has one soft external dependency (unpkg.com must be
reachable); if that ever becomes a concern, the fix is to vendor those three scripts under
`public/vendor/` and point `support.js`'s `REACT_URL`/`REACT_DOM_URL`/`BABEL_URL` at local files.

## How pages are named

The original Claude Designer export named the pages `BioFIA Home.dc.html`, `BioFIA-Alliance.dc.html`,
etc. Those have been renamed to clean, extension-free production URLs (`index.html` → `/`,
`alliance.html` → `/alliance`, and so on) and every internal link was rewritten to match.
`firebase.json` sets `"cleanUrls": true`, which is what lets `/alliance` serve `alliance.html`
without a redirect loop or a rewrite rule.

**If you re-export a page from Claude Designer later**, drop the new `.dc.html` file into `public/`
under the matching clean name (e.g. a re-exported "BioFIA Home" becomes `public/index.html`) and
carry over any `<title>`/`<meta>` tags this repo added inside `<helmet>` — the Designer export
won't include them.

## Local preview

```bash
npm install -g firebase-tools   # once
firebase login
firebase emulators:start --only hosting
```

Then open the URL it prints (defaults to `http://localhost:5000`).

## Deploying

**First deploy / manual deploy**, from the repo root:

```bash
firebase deploy --only hosting
```

**After that**, every push to `main` deploys automatically via
`.github/workflows/firebase-hosting-merge.yml`, and every pull request gets its own preview URL via
`.github/workflows/firebase-hosting-pull-request.yml`. Those workflows need one repo secret,
`FIREBASE_SERVICE_ACCOUNT_BIOFIA`. The easiest way to create it is to run this once from a machine
with access to the `biofia` Firebase project and the GitHub repo:

```bash
firebase init hosting:github
```

Answer its prompts pointing at `gunthar/biofia` — it will create the service account, add the
secret to the repo for you, and can overwrite the two workflow files above with equivalent ones
(safe to accept; they do the same thing).

## Custom domain (biofia.org)

**This project's Firebase infrastructure was originally provisioned for Firebase App Hosting, not
classic Hosting — see `MIGRATION.md` before attaching `biofia.org` to this Hosting site.** Skipping
that will leave the domain pointed at the (unused) App Hosting backend while this repo deploys to
Hosting's default `*.web.app` URL.

## What's deliberately not in this repo

- `uploads/` from the Designer export (raw source photos, the fundraising deck and executive brief
  PDFs, work-in-progress screenshots, and duplicate/renamed logo uploads) — none of it is referenced
  by any page; `public/assets/` already has the curated, correctly-named copies the site actually
  uses. Keeping ~30 MB of internal drafts and screenshots out of a public repo/hosting bucket is
  intentional. If you want those files version-controlled somewhere, put them in a separate,
  non-public storage location rather than this repo.
- Terraform state (`terraform.tfstate*`) and the `.terraform/` provider cache (~125 MB of
  platform-specific binaries) — state should never be committed (it can expose resource metadata,
  and it's the kind of thing that causes real damage if two people apply from stale copies), and the
  provider cache is regenerated by `terraform init`. Only `main.tf` is worth version-controlling, and
  even that arguably belongs in a separate infra repo rather than next to the website's static
  assets.
